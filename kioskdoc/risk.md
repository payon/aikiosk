# 리스크 분석 및 대응 방안

## 1. 기술적 리스크
- **리스크**: Tauri의 Android 지원이 아직 베타/안정화 단계일 수 있음.
  - **대응**: 핵심 키오스크는 Windows/Linux(Tauri)로 고정하고, Android는 검증된 TWA(PWA 래핑) 방식으로 이원화하여 배포.
- **리스크**: 다양한 키오스크 해상도(15/21/32)에서 DnD 레이아웃 깨짐.
  - **대응**: 절대적 픽셀(px) 대신 상대적 단위(%, vw, vh)와 CSS Grid를 강제하는 템플릿 스키마 검증 로직 도입.

## 2. 하드웨어 연동 리스크
- **리스크**: 실제 Bixolon/Posbank 드라이버가 OS 업데이트 또는 특정 키오스크 하드웨어에서 충돌.
  - **대응**: Rust 백엔드와 하드웨어 드라이버 사이에 명확한 추상화 계층(Trait)을 두고, 문제 시 Mock 모드로 자동 폴백(Fallback)하여 교육 기능은 지속되도록 설계.

## 3. 운영/보안 리스크
- **리스크**: 멀티테넌시 환경에서 한 테넌트의 과도한 리소스 사용으로 전체 시스템 장애 (Noisy Neighbor).
  - **대응**: Redis 기반 Rate Limiting 적용, 템플릿 에셋에 대한 CDN 또는 캐싱 정책으로 백엔드 부하 분산.

## 4. 시니어 사용자 리스크
- **리스크**: 복잡한 UI로 인한 사용자 이탈 또는 오작동.
  - **대응**: 모든 템플릿은 '시니어 모드' 검증 체크리스트(폰트 크기, 대비, 버튼 간격)를 통과해야만 배포 가능하도록 Admin UI에 게이트키퍼 기능 추가.

  # [프롬프트 목표] 프로젝트 실행 중 발생할 수 있는 기술적, 운영적 리스크와 대응 방안을 정의한다.

## 1. 기술적 리스크
- **리스크**: 저사양 15인치 키오스크에서 복잡한 차트 또는 고해상도 에셋 로딩 시 메모리 부족(OOM) 또는 프리징.
  - **대응**: 키오스크 클라이언트에는 차트 렌더링 로직을 아예 포함하지 않고, 단순 텍스트/게이지 바만 사용. 무거운 집계와 시각화는 100% 관리자 웹(React)에서 처리. 에셋은 해상도별 자동 다운샘플링.

## 2. 데이터 및 보안 리스크
- **리스크**: 설문 데이터 수집 시 개인정보 유출 또는 악의적인 대량 더미 데이터 주입.
  - **대응**: API 레벨에서 Rate Limiting 적용. 설문 응답 스키마 엄격 검증. 민감 정보는 암호화 저장 및 대시보드에서는 익명 집계값만 노출.

## 3. 운영 리스크
- **리스크**: 센터 관리자의 실수로 잘못된 템플릿이 전체 기기에 배포되어 교육 중단.
  - **대응**: '게시' 시 필수 접근성 검증 게이트 통과 강제. 배포 이력 버전 관리(v1.0, v1.1) 및 대시보드에서의 '원클릭 긴급 롤백' 기능 제공.

  - **리스크**: 동적 SQL 실행 시 SQL 인젝션 취약점 발생 가능.
  - **대응**: 데이터셋 레지스트리에서 관리자가 직접 Raw SQL을 입력하는 것을 제한하고, UI 기반의 쿼리 빌더(Query Builder)를 통해 파라미터화된 쿼리만 생성되도록 강제.
- **리스크**: 복잡한 액션 체인 실행 중 클라이언트 크래시 시 장바구니 데이터 유실.
  - **대응**: Tauri 앱 종료 직전 `beforeunload` 이벤트에서 로컬 SQLite에 전역 상태(Global State)를 스냅샷으로 저장하고, 재실행 시 복구.
