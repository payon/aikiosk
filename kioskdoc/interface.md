# 하드웨어 연동 인터페이스 설계

## 1. 영수증 프린터 (Bixolon)
- **연동 방식**: Tauri Rust Backend에서 `serialport` 크레이트 또는 OS별 프린터 스풀러 API 사용.
- **드라이버 추상화**: `PrinterTrait` 정의. 실제 Bixolon 드라이버와 Mock(시뮬레이션) 프린터 구현체 제공.
- **명어셋**: ESC/POS 명령어 세트 지원 (텍스트 크기 확대, 한글 인코딩 EUC-KR/UTF-8 처리).

## 2. 카드 결제 (Posbank 시뮬레이션)
- **실제 연동**: POS 통신(TCP/Serial) 라이브러리 래핑.
- **교육용 시뮬레이션**: 특정 USB HID 장치(예: 특정 바코드 스캐너 또는 커스텀 버튼 박스) 입력 감지 시, 결제 성공 API를 모킹하고 즉시 프린트 명령을 큐에 적재.

## 3. 물리 입력 장치
- 키보드 이벤트 리스너: `F1`(홈), `F2`(이전), `F3`(도움말/음성 재재생) 등 시니어용 물리 버튼 매핑.
- Tauri `tauri::plugin::global-shortcut` 활용하여 백그라운드에서도 단축키 인식.

# [프롬프트 목표] 물리적 하드웨어 및 외부 시스템과의 연동 인터페이스를 정의한다.

## 1. 동적 하드웨어 추상화 계층 (HAL)
- `Driver Interface`: 모든 드라이버는 `connect()`, `execute(command)`, `disconnect()` 메서드를 구현해야 함.
- **시뮬레이션 모드**: 실제 포트 열기 실패 시, UI에 "교육용 시뮬레이션 모드 활성화" 토스트를 띄우고 가짜 성공 응답을 반환하여 교육 흐름을 끊지 않음.

## 2. 설문 입력 장치 확장성
- 기본 터치스크린 외에, 시니어용 대형 물리 키패드(1, 2, 3, 4, 5번 버튼)가 연결된 경우, 해당 HID 입력을 설문 선택 이벤트로 매핑하는 로직 포함.

- **이벤트 기반 하드웨어 트리거**: 액션 체인 내에서 `[Wait for Barcode Scan]` 노드를 실행하면, Tauri가 USB HID 스캐너 입력을 가로채기(Hook)하여 다음 노드로 데이터를 전달하는 인터페이스 설계.
