# 테스트 주도 개발(TDD) 전략

## 1. 단위 테스트 (Unit Test)
- **Backend**: Rust `#[cfg(test)]`를 이용한 Axum 라우터, 미들웨어(tenant_id 주입), DB 쿼리 테스트.
- **Frontend**: Jest + React Testing Library를 이용한 드래그앤드롭 컴포넌트 및 시니어용 큰 버튼 렌더링 테스트.

## 2. 통합 테스트 (Integration Test)
- 멀티테넌시 격리 테스트: Tenant A의 사용자가 Tenant B의 템플릿에 접근하려 할 때 403 Forbidden 반환 확인.
- 하드웨어 시뮬레이션: Mock 프린터 객체에 데이터 전송 시 예상되는 ESC/POS 문자열 생성 검증.

## 3. E2E 테스트 (End-to-End)
- Playwright 사용.
- 시나리오: 수퍼관리자 로그인 → 새 테넌트 생성 → 서브관리자 로그인 → DnD로 템플릿 수정 → 배포 → 키오스크 클라이언트에서 변경사항 반영 확인.

# [프롬프트 목표] 코드 품질과 안정성을 보장하기 위한 테스트 전략을 정의한다.

## 1. 단위 테스트 (Unit)
- **Rust**: `json_layout` 스키마 검증 로직, 멀티테넌트 미들웨어의 `tenant_id` 추출 로직 테스트.
- **React**: 드래그앤드롭 시 컴포넌트 트리 업데이트 테스트, 접근성(aria-label) 누락 검증 테스트.

## 2. 통합 테스트 (Integration)
- **오프라인 동기화 시뮬레이션**: 네트워크를 차단한 상태에서 설문 제출 → SQLite 큐잉 확인 → 네트워크 복원 → 서버 API 호출 및 큐 비움 검증.
- **RBAC 우회 시도**: Tenant A의 토큰으로 Tenant B의 통계 API를 호출할 때 403 반환 검증.

## 3. E2E 테스트 (Playwright)
- 시나리오: 관리자 로그인 → 새 템플릿에 '이모지 설문' 컴포넌트 추가 → 24인치 프리뷰 확인 → 게시 → 키오스크 에뮬레이터에서 해당 템플릿 로드 및 설문 응답 시뮬레이션 → 대시보드에서 통계 차트 업데이트 확인.

- **액션 체인 검증 테스트**: 수백 가지의 복잡한 시나리오(장바구니 담기 → 옵션 변경 → 결제 실패 → 재시도)를 JSON 포맷으로 정의하고, Rust 백엔드의 Action Executor가 이를 정확히 처리하는지 단위 테스트.
